Mere paas do models hain. Ek ka precision high, doosre ka recall high. Winner kaun?

Agar har meeting mein ye discussion 40 minute chal raha hai, to tumhe metric problem hai, model problem nahi.

Metric problem?

Haan. Team ko ek scoreboard chahiye. Warna har insaan apni favourite number leke argument jeetne aayega.

To ek hi number bana dein?

Mostly yes. Ek optimizing metric rakho jisko improve karna hai. Baaki constraints ko “itna to hona hi chahiye” bana do.

Ek number kyu?

ML project mein speed bahut matter karti hai. Tum 20 models train karoge. Agar har model ke liye 5 numbers compare karne pad rahe hain, decision slow ho jaata hai. Ek number wala metric tumhe quick “A better than B” bolne deta hai.

Ye number perfect sach nahi hota. Ye team ka compass hota hai. Compass thoda rough ho sakta hai, par direction clear honi chahiye.

Precision, recall aur F1

Rare positive problems mein accuracy dhokha deti hai. UPI fraud mein 99.7% transactions genuine hain. “Sabko genuine bolo” to accuracy high, par fraud pakda zero. Yahan precision aur recall kaam aate hain.

precision = TP / (TP + FP) recall = TP / (TP + FN) F1 = 2 × precision × recall / (precision + recall)
  • TP = fraud tha, model ne fraud bola
  • FP = genuine tha, model ne fraud bola; customer irritate
  • FN = fraud tha, model miss kar gaya; paisa gaya
  • F1 = precision aur recall ka balanced single number
ModelTPFPFNPrecisionRecallF1
A80208080/100 = 80%80/160 = 50%2×0.8×0.5/1.3 = 61.5%
B1208040120/200 = 60%120/160 = 75%2×0.6×0.75/1.35 = 66.7%

F1 ke hisaab se B jeeta. Lekin agar FP ka cost bahut high hai, tum F1 ke bajay precision constraint laga sakte ho. Metric business pain se judna chahiye, ego se nahi.

Kai customer segments ka average

Grocery recommendation app bana rahe ho. Dev set mein naye users, weekly buyers, festival shoppers, aur wholesale buyers hain. Har segment ka error alag aa sakta hai. Single metric ke liye average lo, par individual rows bhi dekhte raho.

SegmentErrorNote
Naye users6%History kam
Weekly buyers4%Data stable
Festival shoppers11%Seasonal basket alag
Wholesale buyers7%Bulk pattern
Average(6+4+11+7)/4 = 7%Single score

Average metric useful hai, par "Festival shoppers 11%" row ko ignore mat karo. Product mein ek segment ko consistently kharab experience mil raha ho to team ko pata hona chahiye.

Satisficing vs optimizing

Har number ko maximize karna zaroori nahi. Kuch numbers bas acceptable limit ke andar hone chahiye.

Optimizing metricIsko jitna ho sake improve karna hai. Jaise F1 ya average accuracy.
Satisficing metricBas threshold pass karo. Jaise prediction 100 ms se kam, model size 30 MB se kam.

Example: kirana invoice scanner app bill ki line-items padhkar accounting entry banata hai. Main goal extraction accuracy hai. Par agar bahut bills manual review mein chale gaye ya scan bahut slow hua, shopkeeper use nahi karega.

ModelExtraction accuracyManual reviewLatencyDecision
A94%3.5%420 msPass: optimize accuracy
B95%7.2%390 msReject: review limit fail
C93%2.0%900 msReject: latency limit fail

Yahan rule: maximize extraction accuracy, subject to manual review < 5% and latency < 700 ms. Bas. Debate khatam.

N metrics ka simple rule

Agar N metrics hain, ek ko optimizing banao, baaki N − 1 ko satisficing. Isse team ko pata rahega ki hill kis direction mein chadhna hai, aur kin khaiyon mein nahi girna.

Accuracy/F1
optimize+ Latency
< limit+ Memory
< limit+ Winner
clear choice
Dhyan rakhna: “Accuracy bhi, latency bhi, fairness bhi, size bhi — sab improve karo” bolna strategy nahi hai. Pehle decide karo kaunsa score optimize hoga aur kaunse gate pass karne hain.
Yaad rakhna: Metric meeting ko chhota karta hai. Ek scoreboard banao, constraints likho, phir experiments fast chalao.

Dimaag mein aaye sawaal

F1 hamesha best metric hai?

Nahi. F1 precision aur recall ko equal weight deta hai. Agar cancer screening mein recall bahut zyada important hai, F1 se zyada recall-constrained metric better ho sakta hai.

Average segment error se problem chhup sakti hai?

Haan. Isliye optimizing metric average ho sakta hai, par dashboard mein per-segment breakdown zaroor rakho. Metric decision ke liye hai, aankh band karne ke liye nahi.

Thresholds kaise set karein?

User pain aur system limits se. Agar app 200 ms ke baad slow feel hota hai, latency threshold 200 ms nahi, thoda safe 150 ms rakho.

✍️ Ab tumhari baari (pehle khud socho, phir answer kholna)

Model ne 50 fraud pakde, 10 genuine ko fraud bola, aur 25 fraud miss kiye. Precision, recall, F1?

Precision = 50/(50+10) = 83.3%. Recall = 50/(50+25) = 66.7%. F1 = 2×0.833×0.667/(1.5) ≈ 74.1%. Final answer: F1 ≈ 74%.

Delivery ETA model: error kam karna hai, par response 80 ms se kam aur model 20 MB se kam hona chahiye. Optimizing kya?

Optimizing metric ETA error hoga. Latency < 80 ms aur size < 20 MB satisficing constraints. Final answer: 1 optimizing, 2 satisficing.

Chaar customer segments ke errors 3%, 8%, 5%, 12%. Average?

(3 + 8 + 5 + 12) / 4 = 28/4 = 7%. Final answer: 7%.
