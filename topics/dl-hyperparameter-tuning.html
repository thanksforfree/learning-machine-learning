Mere model mein knobs hi knobs hain: learning rate, layers, units, β, batch size. Main grid bana ke sab try kar dun?

Agar tum chai bana rahe ho, chini 1, 2, 3 chamach aur adrak 1, 2, 3 tukde ka grid chalega. Par deep learning mein knobs ki ginti zyada aur cost mehengi.

To kaise choose karun?

Random search. Par “random” matlab andha nahi. Sahi scale pe random.

Scale?

Learning rate ko 0.0001 se 1 tak equally mat chuno. Log scale pe chuno, warna important chhote values miss ho jaayenge.

Kaunsa hyperparameter kitna important?

Har project alag, par practical priority kuch aisi hoti hai:

Grid search ki jagah random search kyu

Grid mein tum har knob ko fixed lines pe try karte ho. Problem: agar asli important knob α hai, aur doosra knob utna matter nahi karta, to grid bahut attempts waste karega. Random search har trial mein α ki nayi value deta hai.

Coarse to fine: pehle shehar, phir gali

Pehle wide range mein random points try karo. Jahan achhe results mile, us region ke aas-paas zoom in karo. Jaise flat dhundhte waqt pehle area choose, phir society, phir floor.

Learning rate ke liye log scale

α = 0.0001, 0.001, 0.01, 0.1, 1 — inke beech ka farak multiplication mein hai. Isliye r ko random chuno, phir α = 10ʳ.

r ~ uniform(a, b) α = 10ʳ
  • a, b exponent range, jaise −4 se −1
  • uniform matlab r range mein randomly
  • α log scale pe spread hota hai

β ke liye 1 − β sample karo

β = 0.9 aur 0.99 mein bada practical farak hai: average 10 readings vs 100 readings. Agar β ko 0.9 se 0.999 tak normal random chuna, to useful near-1 zones properly cover nahi honge. Isliye s = 1 − β ko log scale pe sample karo.

Tutor mode vs tournament mode

Tutor modeEk student ko personal coaching. Ek model train dekho, α adjust karo, architecture tweak karo. Limited compute ho to useful.
Tournament modePoore batch ko mock test. Bahut saare models parallel chalao, best score wale ko shortlist karo. Compute zyada ho to fast discovery.

Dono valid hain. Laptop pe ho to tutor mode. Cloud budget hai to tournament mode. Bas har experiment ka config aur dev score likhte rehna, warna kal khud ko yaad nahi rahega ki kaunsi chai mein kitni chini thi.

Dobara check: Data badla, architecture badla, ya kuch mahine nikal gaye — hyperparameters dobara tune karo. Purana best hamesha naya best nahi hota.
Dhyan rakhna: Linear random sampling se α ke bade values over-represent ho jaate hain. 0.0001 se 1 tak uniform sample kiya to 0.1 se 1 ke beech hi bahut points girenge, jabki useful zone 0.001 ke aas-paas ho sakta hai.
Yaad rakhna: Random search karo, log scale pe karo, pehle wide jao phir zoom in. Sabse pehle α ko serious lo.

Dimaag mein aaye sawaal

Random search mein kitne trials?

Budget pe depend. 10 trials bhi grid se better signal de sakte hain. Serious project mein dozens ya hundreds. Har trial ka result save karo.

Batch size bhi log scale pe?

Aksar powers of 2 try karte hain: 32, 64, 128, 256, 512. Memory limit bhi decide karti hai.

Dev set pe baar-baar tune karne se overfit?

Haan, possible. Isi liye final test set ko end tak lock rakho. Dev tuning ke baad test pe sirf final honest number.

✍️ Ab tumhari baari (pehle khud socho, phir answer kholna)

r = −3 ho to α = 10ʳ kitna?

10⁻³ = 0.001.

β = 0.99 roughly kitne steps ka average?

1/(1 − 0.99) = 1/0.01 = 100 steps.

Compute kam hai. Tutor mode ya tournament mode?

Tutor mode: ek model ko dhyaan se monitor aur tune karo.
