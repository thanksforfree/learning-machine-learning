Dost, network train ho gaya. Accuracy bhi ek number aa gaya. Ab khush ho jaun?

Thoda ruk. Exam wali analogy le: practice notebook pe 99% score ka matlab board exam mein bhi 99% hoga, ye guarantee nahi.

To phir model ko honest tareeke se kaise pakdein?

Data ko teen dabbon mein baanto: train padhai ke liye, dev model chunne ke liye, aur test final report card ke liye.

Data split: purana rule vs big data rule

Pehle datasets chhote hote the, isliye 60/20/20 split popular tha. Matlab 60% training, 20% dev, 20% test. Par agar tumhare paas 10 lakh examples hain, to dev/test ko 2 lakh examples dena aksar zaroori nahi. 10,000 dev examples bhi model compare karne ke liye kaafi stable ho sakte hain.

Rule ratna nahi hai. Sawaal ye hai: dev set itna bada ho ki do models ka farak reliably dikh jaye, aur test set itna ho ki final number pe bharosa aaye.

Dev aur test same duniya se aane chahiye

Socho tum Zomato review classifier bana rahe ho. Dev set Delhi ke restaurant reviews se hai, test set Mumbai slang wale reviews se. Ab dev pe best model choose karoge, par test pe alag game niklega. Ye aisa hai jaise practice spin bowling pe ki aur final mein fast bouncer aa gaya.

Dhyan rakhna: Dev set ko baar-baar dekh ke model tune karte ho. Isliye test set ko end tak “sealed envelope” rakho. Test pe tune karna cheating jaisa hai.

Sirf dev set, test nahi — kab chalega?

Kabhi project research/learning stage mein hota hai. Tumhe bas model A vs B choose karna hai, public final number report nahi karna. Tab train/dev split se kaam chal sakta hai. Par product launch, paper, client demo, ya benchmark report karna ho, to test set alag rakho.

Dev setRoz ka mock test. Ispe architecture, λ, learning rate, dropout sab choose karte ho.
Test setFinal board exam. Iska number tab bolo jab decisions freeze ho chuke hon.

Bias-variance diagnosis numbers se

Deep learning mein sirf train vs dev gap nahi dekhte. Pehle Bayes error ya human-level error ka andaaza chahiye. Ye woh error hai jo data ke noise ki wajah se practically avoid nahi hota.

Bayes / humanTrain errorDev errorDiagnosis
2%14%17%High bias: train hi weak
2%4%13%High variance: train ratta, dev pe fail
7%9%10%Kaafi theek; Bayes ke paas
2%10%18%Bias bhi, variance bhi
Avoidable bias ≈ train error − Bayes error Variance gap ≈ dev error − train error
  • Bayes error = best possible error ka andaaza, jaise expert human ki galti
  • Avoidable bias bada = model training data pe bhi pattern nahi pakad raha
  • Variance gap bada = model training examples ko zyada yaad kar raha

Basic recipe: pehle bimaari, phir dawa

Train error dekho
Bayes se compare→Dev gap dekho→Action choose karo
ProblemPehla tryDoosra try
High biasBada networkZyada train karo, better optimizer, architecture change
High varianceZyada dataL2, dropout, augmentation, chhota network

Deep learning ka nice part: bada network bias ko ghata sakta hai, aur regularization/data variance ko ghata sakte hain. Matlab dono knobs alag-alag mil jaate hain.

Bias-variance trade-off kam kyu feel hota hai

Classical ML mein model complex karo to bias ghatta, variance badhta. Jaise chhoti chadar: pair dhako to sar khul gaya. Deep learning mein huge network + regularization + data ke saath chadar badi ho gayi. Bada network train error improve kar sakta hai, aur agar dev gap badhe to data/dropout/L2 se sambhal sakte ho.

            train_err = 0.10
            dev_err = 0.18
            bayes_err = 0.02

            avoidable_bias = train_err - bayes_err  # 0.08: train pe abhi kaam baaki
            variance_gap = dev_err - train_err      # 0.08: dev gap bhi bada
Yaad rakhna: Train/dev/test split evaluation ka plumbing hai; bias-variance diagnosis us plumbing se nikla hua doctor report.

Dimaag mein aaye sawaal

Dev set ko validation set bhi bolte hain?

Haan. Deep learning papers mein “dev”, “validation”, “CV” aksar same idea ke naam hain: model choose karne wala set.

Bayes error exact kaise pata chalega?

Exact nahi pata hota. Human expert, label noise, ya domain knowledge se rough estimate banate hain. Rough bhi useful hai, kyunki train error 10% achha hai ya bura, context se hi pata chalega.

Agar dev aur test distribution accidentally alag nikal gaye?

Test number confusing ho jayega. Pehle decide karo real target distribution kya hai, phir dev/test dono ko usi source se dubara banana better hai.

✍️ Ab tumhari baari (pehle khud socho, phir answer kholna)

10,00,000 examples hain. 98/1/1 split mein train/dev/test kitne?

Train 9,80,000; dev 10,000; test 10,000. final answer: 9.8 lakh / 10k / 10k.

Bayes 3%, train 5%, dev 14%. Sabse badi problem?

Train Bayes ke paas hai, par dev gap 9% hai. Ye high variance hai.

Sirf model choose karna hai, public final score nahi dena. Test set zaroori?

Strictly zaroori nahi. Train/dev se kaam chal sakta hai, par final claim ke liye test set rakhna safer hai.
