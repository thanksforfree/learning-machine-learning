Pichhle page mein convolution karte hi 7×7 photo 5×5 ho gayi. Ye to har layer mein photo ko sukha dega?

Bilkul. Agar har baar bina soche filter ghuma diya, to photo chhoti hoti jaayegi aur corner pixels ko kam chance milega.

Corner pixels ko kam chance matlab?

Beech wala pixel kai 3×3 patches mein aata hai. Corner wala sirf ek-do patches mein. Jaise group project mein corner wala dost meeting mein bulaaya hi nahi gaya.

To solution?

Photo ke aas-paas zero ka border laga do. Isko padding kehte hain. Aur jab fast chhota output chahiye, khidki ko ek-ek nahi, do-do kadam chalao — isko stride kehte hain.

Do problems: shrinking aur corner unfairness

Valid convolution matlab filter sirf asli photo ke andar rahe. 7×7 input pe 3×3 filter lagao, stride 1, padding 0:

output = ⌊(n + 2p − f) / s⌋ + 1
  • n = input height/width (square example mein)
  • f = filter size
  • p = padding, photo ke charo taraf kitne zero layers
  • s = stride, filter kitne pixel ka kadam leta hai
  • ⌊ ⌋ = floor, decimal aaye to neeche wala integer
SettingCalculationOutput
valid: n=7, f=3, p=0, s=1⌊(7 + 0 − 3)/1⌋ + 15×5
same: n=7, f=3, p=1, s=1⌊(7 + 2 − 3)/1⌋ + 17×7
stride 2: n=10, f=3, p=1, s=2⌊(10 + 2 − 3)/2⌋ + 1 = ⌊4.5⌋ + 15×5

Padding p: photo ke aas-paas safe border

Padding mein hum input ke border ke bahar zero values add karte hain. Filter jab corner pe aata hai, to uska kuch hissa zero border pe hota hai. Isse two fayde:

  • Output jaldi shrink nahi hota.
  • Corner pixels bhi zyada patches mein participate karte hain.
Valid convolutionp = 0. Filter sirf asli photo ke andar. Output chhota hota hai.
Same convolutionp aisa choose karo ki stride 1 pe output size input jaisa rahe.

Same padding ke liye p = (f − 1)/2

Stride 1 ho aur output ko same size rakhna ho, to formula se:

n = n + 2p − f + 1 ⇒ p = (f − 1) / 2
  • f = 3 ho to p = 1
  • f = 5 ho to p = 2
  • f = 7 ho to p = 3

Isliye CNN mein odd filter sizes popular hain: 3×3, 5×5, 7×7. Odd f mein center pixel clear hota hai aur p integer aata hai. f = 4 pe p = 1.5, matlab half pixel ka border — ajeeb jugaad.

Stride s: filter ke bade kadam

Stride 1 = har next pixel pe khidki. Stride 2 = ek pixel skip karke. Jaise gully cricket mein ball dhundhne ke liye har ghar nahi, alternate ghar check karna — fast, par detail kam.

Stride se computation kam hota hai aur feature map chhota hota hai. Lekin bahut bada stride detail miss kar sakta hai. Chhote object traffic camera mein waise hi mushkil hote hain; stride unhe aur chhupa sakta hai.

Cross-correlation vs convolution — naam ka chhota kissa

Maths wali “true convolution” mein filter ko pehle flip karte hain, phir slide karte hain. Deep learning libraries aam taur pe filter ko flip nahi karti; technically woh cross-correlation hai.

Par CNN duniya mein sab isko convolution hi bolte hain. Kyun? Kyunki filter ke numbers training mein seekhe jaate hain. Flip ho ya na ho, network apna useful filter adjust kar lega. Naam thoda historical hai, tension nahi.

def out_size(n, f, p=0, s=1):
    return (n + 2*p - f) // s + 1

print(out_size(32, 5, p=2, s=1))  # 32: same conv
print(out_size(10, 3, p=1, s=2))  # 5: strided conv
Dhyan rakhna: Agar formula ka numerator stride se exactly divide nahi hota, output floor hota hai. “4.5 positions” jaisi koi cheez nahi; last half-fit window ignore ho jaati hai.
Yaad rakhna: Padding border bachata hai, stride output chhota karta hai, aur output size formula har CNN debugging ka calculator hai.

Dimaag mein aaye sawaal

Padding mein zero hi kyu? Border ka copy kyu nahi?

Zero padding simple aur common hai. Kabhi-kabhi reflection padding bhi use hoti hai, par CNN basics mein zero padding enough hai.

Same padding stride 2 pe bhi same size rakhega?

Nahi. “Same” ka common meaning stride 1 ke liye input jaisa output. Stride 2 lagaoge to output roughly aadha ho jaayega.

Even filter kabhi use nahi karte?

Use ho sakta hai, par 3×3 jaisa odd filter clean center deta hai, isliye bahut common hai.

✍️ Ab tumhari baari (pehle khud socho, phir answer kholna)

28×28 input, f=3, p=1, s=1. Output size?

⌊(28 + 2 − 3)/1⌋ + 1 = 28. 28×28.

15×15 input, f=5, p=0, s=2. Output size?

⌊(15 − 5)/2⌋ + 1 = 5 + 1 = 6×6.

3×3 filter ke saath same padding chahiye. p kitna?

p = (3 − 1)/2 = 1.
