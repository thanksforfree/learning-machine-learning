Convolution se feature maps ban gaye. Par pooling kyu daalte hain?

Pooling ko photo ka “summary mode” samjho. Har chhote area se sabse strong signal rakho, baaki detail thodi chhod do.

Jaise class notes ka short version?

Haan. Agar 2×2 area mein kahin bhi strong edge mila, max pooling bolega: “haan bhai, yahan feature hai.” Exact pixel thoda idhar-udhar ho to bhi chalega.

Iske weights hote hain?

Nahi. Pooling fixed operation hai. Na weights, na bias, na learning. Bas rule follow karta hai.

Average pooling aur parameters ka sach

Average pooling max ki jagah average leta hai. Same top-left block ka average = (1 + 3 + 5 + 6)/4 = 3.75. Modern CNNs mein max pooling common tha; aaj kal kuch architectures stride convolution ya global average pooling use karte hain.

Pooling output size = ⌊(n + 2p − f) / s⌋ + 1 Parameters = 0
  • f = pooling window size
  • s = stride
  • channels = input jaise hi rehte hain; har channel pe pooling separately hoti hai

LeNet-jaisa poora CNN

Ab ek classic pattern dekhte hain: conv, pool, conv, pool, phir fully connected layers. Input 30×30×1 grayscale image maan lo.

Convolution kyu efficient hai?

Parameter sharingEk 5×5 filter ke same weights poori image pe use hote hain. Shirt ka button left mein ho ya right mein, detector same reh sakta hai.
Sparse connectionsEk output pixel sirf nearby input patch dekhta hai, poori image nahi. Local pattern ke liye local connection enough hai.

Dense layer mein har input pixel har neuron se connected hota. CNN bolta hai: “pehle local clues pakdo; global decision baad mein.” Ye photos ke nature se match karta hai.

Translation invariance: thoda khisak gaya to bhi chalega

Socho traffic sign image mein 3 pixels right shift ho gaya. Dense network ke liye input vector bilkul alag positions mein values dega. CNN mein same filter har jagah ghoomta hai, to edge response bhi right taraf shift hoga — ise translation equivariance kehte hain. Pooling paas-paas ki positions ka summary lekar chhote shifts ko kuch had tak tolerate karta hai; poori translation invariance ki guarantee nahi deta.

# One common CNN block
model.add(Conv2D(16, kernel_size=3, activation="relu"))
model.add(MaxPool2D(pool_size=2, strides=2))
model.add(Conv2D(32, kernel_size=3, activation="relu"))
model.add(MaxPool2D(pool_size=2, strides=2))
Dhyan rakhna: Pooling parameters zero hain, par iska matlab ye “free” nahi. Output chhota karke information bhi chhodta hai. Bahut early aggressive pooling se chhote objects gayab ho sakte hain.
Yaad rakhna: Conv features banata hai, pooling summary banata hai, FC/softmax final class choose karta hai.

Dimaag mein aaye sawaal

Pooling har channel ko mix karta hai?

Nahi. Pooling usually har channel pe separately hoti hai. 15×15×18 input pool ke baad 7×7×18 ho sakta hai; depth 18 hi rahegi.

Average pooling kab useful hai?

Jab tum overall presence ka smooth summary chahte ho. Global average pooling final layers mein common hai, jahan har feature map ka average class score mein jaata hai.

FC layers mein parameters itne zyada kyu?

Flatten ke baad har input number har output neuron se judta hai. 882 to 64 layer mein hi 56,000 se zyada weights aa gaye.

✍️ Ab tumhari baari (pehle khud socho, phir answer kholna)

8×8×3 input pe max pool f=2, s=2. Output?

Spatial size 4×4, channels same. 4×4×3.

Conv layer: 8 filters, 3×3×6, bias ke saath parameters?

8 × (3×3×6 + 1) = 8 × 55 = 440.

Parameter sharing ka ek line meaning?

Same filter weights poori image pe reuse hote hain, isliye feature kahin bhi ho, detector kaam kar sakta hai.
