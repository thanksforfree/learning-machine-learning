Model train ho gaya. Ab main khush ho jaun ya pehle check karun?

Pehle check, phir mithai. Agar teacher wahi sawaal exam mein de jo class mein karaye the, marks dhokha ho sakte hain — shayad ratta laga ho. Asli test naye sawaalon se hota hai. Isliye data ko pehle hi teen hisson mein baant do.

Example: polynomial degree kaise chunein

Degree 1, 2, 3 … 10 wale models train karo (sirf training set pe). Har ek ka error CV set pe dekho. Maan lo degree 4 ka CV error sabse kam aaya — degree 4 chuno. Ab test set pe ek hi baar chalao aur wahi number report karo. Test set ko baar-baar dekhna matlab board paper pe pencil se hints likhna.

Sabse common galti: Test set dekh-dekh ke choices karna. Tab test set bhi “mock test” ban jaata hai aur tumhara reported score asal se zyada achha dikhta hai. Real duniya mein surprise milega.

Classification mein error = kitne percent examples galat classify hue.

Numbers ke saath split samjho

Data kam ho to teen hisson mein baantna waste nahi?

Dil karta hai sab training mein daal dein, samajh sakta hoon. Par phir honest report card nahi bachega. Thoda data side mein rakhna insurance jaisa hai.

Maan lo tumhare paas 1000 examples hain. Common split 60/20/20 aise dikhega:

Teen models train kiye. Training error dekh ke degree 6 tempting lag sakta hai, par CV sach bol raha hai.

Ab degree 3 final ho gaya. Test set pe bas ek baar jao. Agar test error 9% aaya, report karo. Test dekh ke phir degree change kiya to fairness gayi.

Data leakage — chhupa hua cheating

Leakage matlab model ko aisi information mil gayi jo real future mein available nahi hogi. Score mast dikhega, deployment pe dhad se girega.

SituationLeakage?Kyu
Same patient ki reports train aur test dono meinHaanModel patient ko pehchaan sakta hai
Future sales column feature meinHaanPrediction time pe future nahi pata
Random customers, no duplicatesMostly okTrain/test independent

Split karte waqt socho: “real world mein model ko ye info milegi kya?” Agar nahi, feature hatao ya split badlo.

Beginner checkpoint: Agar tumne CV set pe 20 models compare kiye, CV score thoda optimistic ho sakta hai. Test set isi final optimism check ke liye bacha ke rakha jaata hai.

Small datasets mein kabhi-kabhi k-fold cross-validation bhi use hota hai: data ko 5 folds mein baanto, 4 se train aur 1 se validate, phir fold rotate. Isse data ka better use hota hai, par training time badhta hai.

Yaad rakhna: Training se seekho, CV se choices karo, test se final honest report do — test ko baar-baar mat chhedo.

Dimaag mein aaye sawaal

60/20/20 fixed rule hai?

Nahi. Data bahut zyada ho (jaise 10 lakh examples) to 98/1/1 bhi theek — 10,000 examples ka test set kaafi hai.

CV set, dev set, validation set — alag hain?

Nahi, aam taur pe teeno same cheez ke naam hain. Team ya library ke hisaab se naam badal jaata hai, kaam wahi: choices compare karna.

Random split karna hai ya time ke hisaab se?

Agar data time-based hai (jaise sales, traffic), future predict karna hai to purane data se train aur naye data se CV/test rakho. Random split kabhi-kabhi future leak kar deta hai.

Test set chhota ho to number hilta kyu hai?

200 examples ke test mein 2-3 extra galtiyan percent ko noticeably badal sakti hain. Isliye possible ho to test set representative aur kaafi bada rakho.

CV error best aur test error thoda worse aaye to?

Normal hai. CV pe choices tune hui hain, test bilkul naya hai. Agar gap bahut bada hai to split mismatch ya data leakage check karo.
