Dev error 12% hai. Main kya improve karun?

Pehle 100 galat examples khol.

Bas dekhna hai? Ye to boring QA ka kaam lag raha hai.

Boring? Dost, yahi gold mine hai. Model ki galtiyan tumhe next sprint ka roadmap deti hain.

Aur agar 100 mein pattern na dikhe?

Tab bhi seekha: problem scattered hai, ek silver bullet nahi. Wo bhi valuable info hai.

100 galat dev examples dekho

Error analysis ka simplest version: dev set ke galat predictions ka random sample lo, manually category mark karo, counts likho. Fancy dashboard baad mein. Pehle aankh se data dekho.

Maan lo warehouse package-damage classifier ka dev set 4,000 photos ka hai. Model 480 galtiyan kar raha hai, yani 12% error. Tum 100 galtiyan sample karke categories mark karte ho.

Category100 galtiyon mein countCeiling improvementFaisla
Plastic wrap glare2828% of 12% = 3.36 pointsHigh ROI
Side-view package222.64 pointsWorth trying
Torn tape hidden111.32 pointsMaybe later
Random confusing cases39MixedNeeds deeper look
ceiling gain ≈ current error × fraction of errors in that category
  • current error = 12% in this example
  • fraction = 28/100 for glare
  • ceiling = maximum possible gain if category magically fixed perfectly

Glare pe kaam karne ka max gain 3.36 points hai. Torn tape hidden ka max 1.32. Agar team chhoti hai, pehle glare.

Galat labels: random vs systematic

Deep learning random label noise se surprisingly tolerate kar leta hai. Agar 1–2% labels randomly wrong hain, bada model average pattern phir bhi seekh sakta hai. Par systematic label errors dangerous hain.

Random label errorKabhi-kabhi annotator ne safe package ko damaged bol diya. Direction random hai.
Systematic label errorEk specific disease ko hamesha “fungus” label kar rahe ho, jab woh nutrient deficiency hai. Model galat rule seekhega.

Systematic error woh hai jo model ke liye fake pattern banata hai. Jaise traffic dataset mein rainy-night images ko mostly “no vehicle” label kar diya kyunki annotator ko vehicle dikha nahi. Model raat+baarish ko “empty road” samajh sakta hai.

Labels theek karne layak kab?

Label cleaning mehenga hai. Numbers se decide karo. Maan lo dev set mein 480 errors hain. Tum 100 error sample dekhte ho, 17 actual label mistakes hain. Current error 12% hai.

ObservationNumberMeaning
Label mistakes among errors17/100 = 17%Noticeable chunk
Ceiling gain12% × 17% = 2.04 pointsCleaning likely worth it
If only 2/100 labels wrong12% × 2% = 0.24 pointsProbably not first priority

Yahan 2.04 points ka possible gain hai. Agar product ke liye 2 points huge hain, label cleaning sprint banao. Agar nahi, glare category shayad better ROI de.

Dev aur test dono pe same process

Agar dev labels clean kiye aur test labels dirty chhode, dev/test comparison unfair ho jaayega. Jo label-cleaning rule dev pe lagao, wahi test pe bhi lagao. Aur sirf wrong predictions nahi, kuch correct examples bhi dekho.

Kyu? Agar “correct” examples mein bhi labels wrong hain, model ko galat tarah reward mil raha ho sakta hai. 100 wrong + 100 correct sample check karna boring lagta hai, par trust banata hai.

Pehla system jaldi banao

Error analysis tabhi possible hai jab model mistakes kare. Isliye months tak perfect data pipeline ka wait mat karo. Ek simple baseline banao, dev set pe run karo, galtiyan dekho, phir iterate.

Quick baseline→ Error analysis→ Targeted fix↻ Better model
Dhyan rakhna: “Mujhe already pata hai problem kya hai” bolke error analysis skip mat karo. Data aksar tumhari ego se better bolta hai.
Yaad rakhna: 100 galtiyan manually dekhna chhota kaam lagta hai, par wahi tumhe 1000 random experiments se bachata hai.

Dimaag mein aaye sawaal

100 examples enough hain?

Direction ke liye haan. Agar category close call ho ya business decision bada ho, 200–500 sample lo. Start 100 se karo; paralysis se better hai.

Categories kaun banata hai?

Pehle rough categories tum banao. Domain expert ke saath 20 examples dekho, categories refine karo. Perfect taxonomy se pehle useful taxonomy chahiye.

Correct examples dekhna kyu?

Label noise correct predictions mein bhi ho sakta hai. Agar label hi wrong tha aur model ne us wrong label ko match kiya, metric model ko galat tareef de raha hai.

✍️ Ab tumhari baari (pehle khud socho, phir answer kholna)

Dev error 9%. 100 errors mein 24 "glare packages" hain. Ceiling gain?

Gain ≈ 9% × 24% = 2.16 percentage points. Final answer: max around 2.16 points.

100 errors mein wrong labels 5 hain. Current error 11%. Label cleaning first priority?

Ceiling = 11% × 5% = 0.55 points. Shayad first priority nahi, unless safety/legal reason ho. Final answer: generally no.

Dev labels clean kiye, test labels nahi. Problem?

Dev/test comparison unfair ho gaya. Same cleaning rules test pe bhi lagao. Final answer: dono pe same process.
