Mini-batch gradient descent mein line zig-zag kyu chalti hai? Seedha best point ki taraf kyu nahi jaati?

Socho tum gali mein cycle chala rahe ho. Road ke dono side speed breakers hain. Tumhara target seedha aage hai, par cycle left-right hil rahi hai.

To handle pakad ke average direction mein chalna padega?

Exactly. Momentum handle ko stable karta hai. RMSprop side wali hila-hili ko dabaata hai. Adam dono ka combo pack hai.

Adam matlab optimizer ka jugaadu dost?

Haan, par jugaad nahi — moving averages ka disciplined use.

Momentum: gradients ka moving average

Har mini-batch ka gradient thoda noisy hota hai. Momentum bolta hai: “ek batch ki cheekh pe mat nacho, recent gradients ka smooth direction dekho.”

v_dW = βv_dW + (1 − β)dW W = W − αv_dW
  • dW = current mini-batch ka gradient
  • v_dW = gradient ka moving average
  • β aksar 0.9, matlab roughly 10 batches ki memory
  • α = learning rate, actual kadam ka size

RMSprop: bade gradient wali direction ko thoda slow

Kabhi ek direction mein gradient bahut bada hota hai, doosri mein chhota. Result: patli gali mein cycle jaise left-right ping-pong. RMSprop squared gradients ka moving average rakhta hai aur update ko uske square-root se divide karta hai.

s_dW = βs_dW + (1 − β)(dW)² W = W − α × dW / (√s_dW + ε)
  • s_dW = squared gradients ka moving average
  • √s_dW bada ho to us direction ka step chhota
  • ε chhota number, zero se divide hone se bachata hai

(6, 1)(13.19, 0.27)patli gali mein zyada stable

Adam = Momentum + RMSprop + bias correction

Adam do diaries rakhta hai: v gradients ka average, s squared gradients ka average. Dono v_0 = 0 se start hote hain, isliye first steps mein bias correction lagti hai.

v = β₁v + (1 − β₁)dW s = β₂s + (1 − β₂)(dW)² v_corrected = v / (1 − β₁ᵗ) s_corrected = s / (1 − β₂ᵗ) W = W − α × v_corrected / (√s_corrected + ε)
  • β₁ = 0.9 momentum wali memory
  • β₂ = 0.999 squared-gradient wali lambi memory
  • ε = 10⁻⁸ default chhota safety number
Hyperparameter sach: Adam mein aksar β₁, β₂, ε ko default chhod dete hain. Sabse zyada tuning learning rate α ki hoti hai. α galat hua to Adam bhi gussa ho jaata hai.
optimizer = tf.keras.optimizers.Adam(learning_rate=0.001)
with tf.GradientTape() as tape:
    loss = model_loss(x_batch, y_batch)
grads = tape.gradient(loss, model.trainable_variables)
optimizer.apply_gradients(zip(grads, model.trainable_variables))  # Adam update

Dimaag mein aaye sawaal

Kya Adam hamesha best hai?

Nahi. Bahut projects mein Adam se fast start milta hai. Kabhi SGD + momentum final performance mein achha ho sakta hai. Par beginner ke liye Adam safe default hai.

RMSprop mein squared gradient kyu?

Square sign ko hata deta hai aur bade gradients ko aur clearly bada dikhata hai. Direction nahi, magnitude ki aadat measure karni hai.

β₂ itna 0.999 kyu?

Squared gradients noisy hote hain. Unka stable estimate chahiye, isliye lambi memory. β₁ ko gradients ki direction ke liye thoda faster rakhte hain.

v = 0.9 × 2 + 0.1 × 6 = 1.8 + 0.6 = 2.4.

Adam mein kaunse hyperparameter ko sabse pehle tune karoge?

α learning rate. β₁, β₂, ε ko pehle default rakhna practical hota hai.

RMSprop denominator bada ho gaya. Step bada hoga ya chhota?

Chhota, kyunki update gradient ko denominator se divide karta hai.
