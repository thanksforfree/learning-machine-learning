Backprop code likh diya, loss bhi chal raha hai. Trust kar loon?

Backprop pe thoda healthy shak rakho. Ye Excel formula jaisa hai: ek cell galat, poori sheet confident jhooth bol sakti hai.

To check kaise karun?

Parameter ko thoda plus karo, thoda minus karo, cost ka difference dekho. Numerical derivative se backprop gradient compare karo.

Numerical derivative: center se naapna

Agar θ ko thoda hilaane se cost kitna badalta hai, wahi gradient ka estimate hai. Better estimate ke liye θ+ε aur θ−ε dono use karte hain.

gradapprox = (J(θ + ε) − J(θ − ε)) / (2ε)
  • θ = koi ek parameter, jaise W ka ek number
  • ε = chhota number, often 10⁻⁷
  • gradapprox = numerical slope
J(θ) = θ², θ = 3, ε = 0.0001Value

Do-taraf wala one-taraf se accurate kyu

One-sided estimate (J(θ+ε)-J(θ))/ε bhi slope deta hai, par usme curve ki tedhapan ka error zyada bachta hai. Two-sided estimate θ ke dono sides dekhta hai, errors ka kaafi hissa cancel ho jaata hai. Jaise gali ki width naapni ho to sirf left wall se nahi, dono walls ke beech naapoge.

Saare parameters ko ek bada θ vector banao

Network mein W[1], b[1], W[2], b[2] alag shapes mein hote hain. Gradient checking ke liye sabko unroll karke ek long vector θ banao. Gradients dW/db ko bhi same order mein vector banao. Phir har index pe θᵢ ko plus/minus ε karke gradapproxᵢ nikalo.

W, b dictionaries→θ vector→grad vector compare↻
for i in range(theta.size):
    theta_plus = theta.copy()
    theta_minus = theta.copy()
    theta_plus[i] += epsilon
    theta_minus[i] -= epsilon
    gradapprox[i] = (J(theta_plus) - J(theta_minus)) / (2 * epsilon)

Compare formula aur thresholds

Direct difference chhota ya bada scale pe depend karega. Isliye relative difference use karte hain.

difference = ||grad − gradapprox||₂ / (||grad||₂ + ||gradapprox||₂)
  • || · ||₂ = L2 norm, vector ki length
  • 10⁻⁷ ke aas-paas = usually excellent
  • 10⁻⁵ = maybe okay, components inspect karo
  • 10⁻³ ya zyada = strong bug smell
DifferenceMeaningAction
10⁻⁷Backprop likely sahiProceed
10⁻⁵BorderlineLayer-wise check
10⁻³Bug likelyStop and inspect

Practical tips: gradient check ko responsibly use karo

  • Sirf debug mein: Har training iteration pe gradient checking bahut slow hai.
  • Components dekho: Agar overall difference high hai, kaunsa layer/index fail kar raha, print karo.
  • Regularization jodo: Agar cost mein L2 hai, numerical J mein bhi L2 term hona chahiye.
  • Dropout band: Random masks numerical check ko unstable banayenge. keep_prob = 1 rakho.
  • Random init aur thodi training ke baad: Kabhi bug sirf non-zero weights pe dikhta hai, isliye dono moments pe check useful.
Dhyan rakhna: Gradient checking pass hone ka matlab model design perfect nahi. Bas backprop formulas cost ke saath match kar rahe hain.
Yaad rakhna: Backprop fast hai, numerical gradient slow hai; slow wale ko inspector bana ke fast wale ko verify karo.

Dimaag mein aaye sawaal

ε kitna rakhein?

Common choice 10⁻⁷. Bahut bada hua to approximation rough, bahut chhota hua to floating point noise aa sakta hai.

Mini-batch pe gradient check kar sakte?

Haan, chhote fixed mini-batch pe karo. Random shuffle/dropout off rakho taaki J repeatable ho.

Autograd frameworks mein zaroori hai?

Agar custom backward likh rahe ho to useful. Pure TensorFlow/PyTorch standard ops mein usually framework gradients reliable hote hain.

✍️ Ab tumhari baari (pehle khud socho, phir answer kholna)

J(θ)=θ², θ=4. True gradient?

Derivative 2θ hai, to 2×4 = 8. final answer: 8.

Gradient check difference 10⁻³ aa raha hai. Ignore karun?

Nahi. Ye bug ka strong signal hai. Layer-wise components inspect karo.

Dropout on rakh ke gradient check kyu problematic?

Har cost call mein random mask badal sakta hai, to J(θ+ε) aur J(θ−ε) same function ke values nahi rahenge.
