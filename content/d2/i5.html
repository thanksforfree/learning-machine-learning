Gradient descent slow chal raha hai. Learning rate badhaun?

Pehle features ki units dekho. Agar ek feature rupees mein 1,00,000 tak hai aur doosra rating 1 se 5, to cost ki katori lambi-sankri ban sakti hai.

Katori ka shape training speed ko kaise affect karta hai?

Gol katori mein seedha neeche jaoge. Lambi katori mein ping-pong karoge. Input normalization katori ko zyada gol banata hai.

Mean ghataao, variance se scale karo

Normalization ka common recipe: training data ka mean μ nikalo, har value se μ subtract karo, phir standard deviation σ se divide karo. σ variance ka square root hota hai. Result: feature ka center 0 ke paas, spread 1 ke paas.

x_norm = (x − μ) / σ σ = √(variance)
  • μ = training feature ka average
  • variance = values average se kitni phaili hain
  • σ = standard deviation, same unit mein spread

mu = X_train.mean(axis=0, keepdims=True)
sigma = X_train.std(axis=0, keepdims=True)

X_train_norm = (X_train - mu) / sigma  # train se μ, σ seekho
X_test_norm = (X_test - mu) / sigma    # test pe wahi μ, σ use karo

Test data pe training wala μ aur σ²

Ye point chhota lagta hai, par bugs ka king hai. Dev/test data ka apna mean nikaal ke normalize kar diya to tum future information use kar rahe ho. Real life mein naye user ke data ka distribution pehle se nahi pata. Isliye train se μ aur σ store karo, wahi dev/test/inference pe lagao.

Dhyan rakhna: Train aur test ko alag-alag normalize karna exam ke answer key jhaankne jaisa ho sakta hai. Scaling parameters sirf training set se fit karo.

Lambi katori vs gol katori

Suppose ek feature 0 se 1 hai, doosra 0 se 10,000. Cost surface ek lambi valley banata hai. Gradient descent ek side se doosri side zig-zag karta rahega. Normalize karne se features comparable scale pe aa jaate hain, valley zyada gol hoti hai, aur larger learning rate safely use kar sakte ho.

Kab zaroori, kab farak kam?

Zaroori jaisaFeatures ki scales bahut different, gradient descent slow, tabular data, custom network from scratch.
Farak kamFeatures already same scale, batch norm layers strong, ya tree models. Phir bhi neural nets mein normalize karna safe default hai.

Normalization accuracy ka magic button nahi. Ye optimization ko easy banata hai. Matlab same model kam epochs mein achha point tak pahunch sakta hai.

If X has shape (m, n): μ has shape (1, n) σ has shape (1, n)
  • m = examples
  • n = features
  • keepdims se broadcasting clean rehti hai
Yaad rakhna: Normalize inputs = optimizer ko seedhi road dena. Model wahi hai, bas safar smooth ho gaya.

Dimaag mein aaye sawaal

Mean 0 aur variance 1 exactly hona zaroori?

Nahi, exact nahi. Bas features comparable scale pe aa jaayein. Floating point aur batches ki wajah se slight difference normal hai.

σ zero ho to?

Feature constant hai, information nahi de raha. Usko drop karo ya denominator mein chhota ε add karo to avoid divide-by-zero.

Labels y normalize karne hote hain?

Classification mein usually nahi. Regression mein kabhi-kabhi y scale karna useful hota hai, par prediction ko wapas original unit mein convert karna padega.

✍️ Ab tumhari baari (pehle khud socho, phir answer kholna)

μ = 50, σ = 10, x = 80. Normalized value?

(80 − 50) ÷ 10 = 3. final answer: 3.

Dev set normalize karte waqt μ aur σ kahan se loge?

Training set se. Dev/test ka apna mean/std fit nahi karna.

Normalization se model ki capacity badhti hai?

Nahi. Ye mainly optimization ko fast/stable banata hai, jaise road smooth karna.
