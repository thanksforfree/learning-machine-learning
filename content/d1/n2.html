Mere phone mein photo to photo dikhti hai. Model ko woh kaise dikhate hain?

Model ko photo nahi, numbers ki plate milti hai. Har pixel ke red-green-blue values. Bas wahi uski duniya hai.

To kya hum photo ko tod-phod ke list bana dete hain?

Haan, bilkul. Jaise suitcase pack karne ke liye kapde fold karke ek line mein rakhte ho. Cheez wahi, arrangement alag.

Aur label bas 1/0? Thoda zyada simple nahi?

Simple hi strength hai. “Cup hai ya nahi”, “defect hai ya nahi”, “spam hai ya nahi” — duniya ke kaafi kaam haan/na se shuru hote hain.

Notation mein x⁽ⁱ⁾, nₓ, m dekh ke thoda darr lag raha hai.

Darr normal hai. Aaj in symbols ko naam aur ghar de dete hain. Phir aage formulas kam scary lagenge.

Binary classification: ek switch wala sawaal

Binary classification ka matlab output do options mein se ek. Spam ya not spam. Defective ya okay. Photo mein cat hai ya nahi. Page pe “cat” example common hai, par tum isko “chai ki photo mein cup hai ya nahi” bhi soch sakte ho. Model ka kaam chance dena hai, phir threshold se 0/1 decide karna.

ŷ = P(y = 1 | x), y ∈ {0, 1}
  • x = input features, photo ke pixels ki list
  • y = true label, 1 ya 0
  • ŷ = model ka estimated chance ki label 1 hai

32×32×3 photo ko 3072 numbers banana

Colour photo mein har pixel ke 3 values hote hain: red, green, blue. Agar photo 32 by 32 hai, total numbers = 32 × 32 × 3 = 3072. Ye numbers ek vector mein khul jaate hain. Jaise kapdon ki almari ko ek lambi line mein rakh diya.

Notation: nₓ, m, x⁽ⁱ⁾, y⁽ⁱ⁾

nₓ features ki ginti hai. Ek 32×32×3 photo ke liye nₓ = 3072. m training examples ki ginti hai. x⁽ⁱ⁾ i-th photo ka vector, aur y⁽ⁱ⁾ uska label. Superscript example number batata hai, power nahi. Haan, notation pehli baar thoda khichdi lagti hai.

X aur Y ka shape

Course convention mein examples columns mein rakhe jaate hain. Matlab X ka har column ek x⁽ⁱ⁾. Isliye X shape hota hai (nₓ, m). Y ek row hai jisme labels columns ke saath align hote hain, to Y ka shape (1, m).

X = [x⁽¹⁾ x⁽²⁾ ... x⁽ᵐ⁾], shape = (nₓ, m) Y = [y⁽¹⁾ y⁽²⁾ ... y⁽ᵐ⁾], shape = (1, m)
  • Rows = features
  • Columns = examples

Example: 500 photos hain, har photo 3072 numbers ki. X shape = (3072, 500). Y shape = (1, 500). Ye convention vectorization mein kaam aata hai, kyunki ek matrix operation se saare examples ka prediction nikal sakte ho.

import numpy as np
image = np.zeros((32, 32, 3))
x = image.reshape(32 * 32 * 3, 1)  # (3072, 1)
X = np.zeros((3072, 500))          # 500 photos columns mein
Y = np.zeros((1, 500))              # 500 labels

Convention ka payoff: columns examples kyu?

Jab examples columns mein hote hain, ek wᵀX se sab predictions ek saath nikalte hain. Agar tum rows-examples style use karte ho to bhi maths possible hai, par formulas transpose ho jaate. Course mein ek convention pakad ke chalna mental load kam karta hai.

Dhyan rakhna: (m, nₓ) aur (nₓ, m) ko mix mat karna. Dono valid styles hain, par is course mein columns examples hain. Shape print karte rehna.
Yaad rakhna: Ek photo vector x hai; poora dataset X hai; X mein columns examples hain.

Dimaag mein aaye sawaal

Flatten karne se photo ka 2D structure lost nahi hota?

Is first model mein haan, nearby pixels ka special relation use nahi hota. CNN later isi weakness ko fix karega. Abhi notation seekhna goal hai.

y ko row vector kyu rakha?

Taaki predictions A bhi (1, m) aaye aur A − Y seedha ho jaye. Broadcasting aur vectorization clean rehte hain.

Pixel values 0 se 255 rahenge?

Usually unhe 255 se divide karke 0–1 range mein laate hain. Training ko numbers chhote aur stable pasand aate hain.

32×32 hi kyu? Real photos to bade hote hain.

32×32 teaching ke liye manageable size hai. Real projects mein photos 224×224, 512×512 ya aur bade ho sakte hain. Principle same: height × width × channels.

Examples columns mein rakhna compulsory hai?

Nahi, libraries mein rows-as-examples bhi common hai. Par is course ke formulas columns convention follow karte hain. Ek convention pakadna debugging ko easy banata hai.
