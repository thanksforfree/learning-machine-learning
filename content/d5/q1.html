Dost, sentence, audio, DNA… in sab mein neural network ko alag kya problem aati hai?

Simple si baat: yahan order hero hai. “Maine chai pi” aur “chai ne mujhe pi” mein same words hain, par meaning full comedy ban gaya.

Toh rows-columns wali fixed table kaam nahi karegi?

Kabhi karegi, par awkward. Sequence data ka length badalta rehta hai, aur har position ka role context se badalta hai. Isliye pehle notation set karte hain, warna aage sab dhundla lagega.

Sequence examples — jahan pehle-aaya/baad-mein-aaya matter karta hai

Socho tum WhatsApp voice note sun rahe ho. “Kal aa raha hoon” mein kal pehle aaya, phir action. Agar audio ke chhote-chhote frames ulat do, awaaz robot nahi, blender jaisi lagegi. Sequence model isi order ko respect karta hai.

Notation: pehle symbols se dosti

Sequence pages mein baar-baar ye likha milega: x⟨t⟩. Iska matlab hai input ka t-th time step. Speech mein t-th audio frame, sentence mein t-th word.

x⟨t⟩ = input at time step t Tₓ = input sequence ki length Tᵧ = output sequence ki length x⁽ⁱ⁾⟨t⟩ = i-th training example ka t-th item
  • t = position, jaise 1st word, 2nd word.
  • i = dataset mein kaunsa example. Example 7 ka 3rd word: x⁽⁷⁾⟨3⟩.
  • Tₓ aur Tᵧ alag ho sakte hain. Hindi sentence 5 words ka, English translation 7 words ki ho sakti hai.

Vocabulary: model ka dictionary shelf

Computer raw word ko samajhta nahi. Hum pehle ek fixed vocabulary banate hain: maan lo 10,000 common words. Har word ko ek index milta hai, bilkul library shelf number jaisa.

IndexTokenOne-hot vector ka idea
1aaj[1, 0, 0, 0, 0, …]
2chai[0, 1, 0, 0, 0, …]
3match[0, 0, 1, 0, 0, …]
10,000<UNK>[0, 0, 0, 0, …, 1]

One-hot vector mein length vocabulary jitni hoti hai. Sirf apne word wale index pe 1, baaki sab 0. Agar vocabulary 10,000 hai, toh “chai” ka vector 10,000 numbers ka hoga; bas ek jagah 1.

<UNK> ka kaam: Unknown word ke liye safety net. Agar model ne “jhakkas-est” kabhi nahi dekha, toh crash karne ke bajay usko <UNK> token de do.

Tokenization ka tiny code

vocab = {"aaj": 1, "chai": 2, "match": 3, "<UNK>": 10000}
sentence = "aaj samosa chai"
ids = [vocab.get(w, vocab["<UNK>"]) for w in sentence.split()]
print(ids)  # [1, 10000, 2] — samosa vocab mein nahi tha
Dhyan rakhna: One-hot vector word ka meaning nahi batata. “chai” aur “coffee” vectors utne hi alag dikhte hain jitne “chai” aur “rocket”. Meaning wali representation embeddings mein aayegi.
Yaad rakhna: Sequence = ordered items. x⟨t⟩ time step hai, Tₓ length hai, vocabulary shelf hai, one-hot shelf number ka signal hai.

Dimaag mein aaye sawaal

Har sentence ko same length banana zaroori hai?

Training batch ke andar padding lag sakti hai, par conceptually sequence ki asli length Tₓ alag-alag ho sakti hai.

<EOS> aur <UNK> dono token hain?

Haan. <EOS> bolta hai “sentence khatam”. <UNK> bolta hai “ye word vocabulary mein nahi mila”.

Vocabulary 10,000 hi kyu?

Ye fixed rule nahi. Chhote app ke liye 5,000, bade corpus ke liye 50,000 bhi ho sakta hai. Trade-off: zyada words = kam unknown, par model bada.

✍️ Ab tumhari baari (pehle khud socho, phir answer kholna)

Sentence “kal train late thi” mein Tₓ kitna hai?

4 words hain, isliye Tₓ = 4.

Vocabulary size 8,000 hai. One-hot vector mein kitne 1 honge?

Har word ke vector mein sirf ek active shelf hota hai. Isliye 1 value 1 hogi, baaki 7,999 zeros.

Agar “vada-pav” vocab mein nahi hai to kaunsa token use karoge?

Usko <UNK> se replace karenge, taaki model safely process kar sake.
