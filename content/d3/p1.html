Worked example: electricity-theft detector

Bijli board ka model unusual meter readings flag karta hai. Numbers dekho:

CheckErrorGapDiagnosis
Field auditor4%—Approx baseline
Train16%16 − 4 = 12%Train pe hi weak: bias
Dev18%18 − 16 = 2%Variance chhoti

Is case mein “aur data lao” shayad first move nahi. Model training set pe hi auditor se 12 points door hai. Pehle model/feature side ko strong karo.

avoidable bias = train error − baseline error variance gap = dev error − train error
  • baseline = insaan, purana system, ya best-known process ka error
  • avoidable bias bada ho to model abhi training data bhi nahi pakad raha
  • variance gap bada ho to model training examples se zyada chipak gaya

Early stopping orthogonal kyu nahi?

Early stopping matlab dev error badhne lage to training rok do. Sunne mein nice. Par ye ek knob se do kaam kar raha hai:

  • Optimization: model ko train loss kam karne ke liye kitna time do?
  • Regularization: model ko overfit hone se kaise rokna?

Jaise scooter ka accelerator aur brake ek hi handle pe ho. Chalega, par control clean nahi. Orthogonal style mein pehle model ko achhe se optimize karo, phir overfitting ke liye L2, dropout, data, augmentation jaise clearer knobs use karo.

Real project tip: Early stopping kabhi-kabhi practical hota hai, especially compute bachane ke liye. Bas usko “perfect clean knob” mat samjho. Debugging mein pehle simple, alag-alag controls better hote hain.
Dhyan rakhna: Metric, dev set, architecture, regularization sab ek hi experiment mein change mat karo. Agar result improve hua, credit kisko doge? Agar kharab hua, blame kisko doge?
Yaad rakhna: Strategy ka goal hero banna nahi; random mehnat ko bachana hai. Broken link pakdo, us link ka clean knob ghumao.

Dimaag mein aaye sawaal

Kya hamesha ek hi change karna zaroori hai?

Research mode mein haan, clarity ke liye. Emergency production bug mein kabhi-kabhi bundle change karna padta hai. Par baad mein isolate karke samjho, warna same bug dobara aayega.

Baseline nahi pata to?

Chhota manual audit karo. 100 examples pe expert ya team ka best guess lo. Perfect baseline nahi chahiye; direction ke liye rough anchor bhi kaafi help karta hai.

Real world fail ho raha hai par test achha hai. Kya karun?

Metric ya test distribution users jaisi nahi hai. Pehle nishaana badlo: real user examples se dev/test refresh karo, phir model improve karo.
