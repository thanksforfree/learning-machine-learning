Diagnosis bol raha hai data mismatch. Ab exact fix kya hai?

Kaash ek universal button hota: “mismatch hatao”. Reality mein pehle farak samajhna padta hai.

Matlab phir se examples dekhne padenge?

Haan dost. Train examples aur dev examples side-by-side kholo. Data ki smell lo. Kabhi camera angle, kabhi mic, kabhi user behaviour.

Aur phir?

Training data ko dev jaisa banao — real data collect karke, ya carefully synthetic data banake.

Train aur dev ka farak khud dekho

Data mismatch spreadsheet se poora samajh nahi aata. 50 train examples aur 50 dev examples open karo. Differences likho. Ye detective work hai.

Receipt OCR project mein train data flat scanner bills se tha, dev data shop-counter phone photos se. Error analysis mein ye differences dikhe:

Paper shapeSeedha, flatMuda hua, corners cutFold augmentation

Ab “data mismatch” vague nahi raha. Tumhe pata hai kis tarah ka data chahiye.

Training data ko dev jaisa banana

Best fix usually real target-style data collect karna hai. Agar users low-end phones use karte hain, low-end phone photos lao. Agar bills folded aate hain, folded bills collect karo. Agar counter glare common hai, glare wale examples lao.

Mismatch dekho→ Target-like examples lao→ Train mix update→ Dev pe check

Target data kam ho to usko carefully train mein add karo, par dev/test holdout bachao. Sab train mein daal diya to compass kho jaayega.

Artificial data synthesis

Jab real target data expensive ho, synthetic data help kar sakta hai. Receipt example: clean bill images hain, aur alag-alag counter backgrounds, folds, shadows ki library hai. Inko combine karke shop-counter jaisi images banao.

synthetic receipt = clean bill + fold/blur + shadow background
  • clean bill = text aur label wahi rehta hai
  • fold/blur = phone photo wali imperfection add karta hai
  • shadow background = counter, plastic bag, hand shadow jaisi real cheezein

Dimaag mein aaye sawaal

Kya synthetic data hamesha real data se worse hai?

Nahi. Good synthesis bahut useful ho sakti hai, especially audio noise, image crop, brightness, simulation. Par uski variety aur realism check karna padta hai.

Target data bahut kam hai. Train mein daalun ya dev mein?

Thoda dev/test ke liye bachao. Baaki train mein use karo. Compass ke bina improvement andhere mein teer hai.

Mujhe mismatch categories nahi mil rahi.

Sample badhao, domain expert ko bithao, metadata dekho: device, time, location, user type. Kabhi mismatch hidden metadata mein hota hai.

✍️ Ab tumhari baari (pehle khud socho, phir answer kholna)

Train-dev 6%, dev 18%. 100 dev errors mein 35 "glare" cases. Mismatch gap ka ceiling?

Mismatch gap = 18 − 6 = 12 points. Glare ceiling = 35% × 12 = 4.2 points. Final answer: max around 4.2 points.

Sirf 25 shadow overlays se 2 lakh synthetic receipts banaye. Risk?

Model un 25 exact shadow patterns pe overfit kar sakta hai. More varied shop lighting chahiye. Final answer: small-source overfitting risk.

Train bills scanner se, dev bills phone camera se. First action?

Scanner vs phone examples side-by-side dekho: fold, glare, background, blur. Phir phone-style data collect/augment karo. Final answer: mismatch audit first.
