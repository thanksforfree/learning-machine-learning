Ab tak single grey photo jaisa lag raha tha. Asli photo RGB hoti hai. Filter teen channels mein kaise chalega?

Good catch. RGB photo ek flat paper nahi, ek volume hai: height, width, depth. Filter bhi utni hi depth ka hota hai.

Matlab 4×4 filter nahi, 4×4×3?

Exactly. Filter ek chhota dabba hai. Woh red, green, blue teenon layers ko ek saath dekhta hai, multiply-sum karta hai, aur ek number deta hai.

Aur agar 12 filters hon?

To 12 alag feature maps milenge. Ek vertical edge, ek green texture, ek corner, ek kuch aur. Output ka depth filters ki count ban jaata hai.

9×9×3 photo par 4×4×3 filter

Input: 9 height, 9 width, 3 channels. Filter: 4 height, 4 width, 3 channels. Notice karo: filter ki depth input ke channels ke barabar honi chahiye.

9×9×3 * 4×4×3 ⇒ 6×6×1
  • Height/width: (9 − 4) + 1 = 6, no padding, stride 1
  • Depth: ek filter ek hi 2D feature map banata hai
  • Filter ke numbers: 4 × 4 × 3 = 48 weights

Ek output number ke liye 48 pair multiply hote hain, phir sab add. RGB mein filter keh sakta hai: “red edge strong hai par blue nahi”, ya “teeno channels mein same boundary hai”.

Kai filters = output ke kai channels

Ek filter sirf ek tarah ka clue pakad sakta hai. Photos mein clues ki line lagi hoti hai: edges, corners, dots, color changes, texture. Isliye layer mein bahut filters rakhte hain.

Output ka n_C filters ki count hai. Har output channel ek filter ka response map hai.

Ek conv layer: convolution + bias + ReLU

Layer ka raw output Z hota hai. Har filter ke saath ek bias number add hota hai. Phir activation, usually ReLU, negative scores ko 0 kar deta hai.

Input volume→Filters slide→+ bias→ReLU→Activation volume
Z[h,w,k] = filter_k · patch + b_k A[h,w,k] = max(0, Z[h,w,k])
  • k = kaunsa filter / output channel
  • patch = input ka chhota 3D dabba
  • b_k = har filter ka ek bias

Notation: n_H, n_W, n_C

CNN notes mein shapes aise likhte hain:

  • n_H = height
  • n_W = width
  • n_C = channels
  • Filter shape = f × f × n_C_prev
  • Weights = f × f × n_C_prev × n_C_current
# Keras style shape socho: height, width, channels
layer = Conv2D(filters=12, kernel_size=4, padding="valid")
# input: 9×9×3  => output: 6×6×12
# params: 12 * (4*4*3 + 1) = 588

Dimaag mein aaye sawaal

Filter RGB channels ko alag-alag output deta hai?

Nahi. Ek 4×4×3 filter teeno channels ka sum karke ek number deta hai. Alag output channels ke liye alag filters chahiye.

ReLU convolution ke baad hi kyu?

Convolution linear score deta hai. ReLU non-linearity add karta hai, warna layers stack karne ka fayda bahut kam ho jaata.

Output width odd/even ka issue hota hai?

Formula floor use karta hai. Architecture banate waqt sizes check karna padta hai, warna flatten se pehle unexpected shape aa sakta hai.
