Server pe model chal gaya, par phone pe lag kar raha hai. Ab?

Yahi real duniya hai dost. Har user ke paas fancy GPU nahi hota. Mobile model ko kam memory, kam battery, kam latency mein chalna padta hai.

To accuracy sacrifice?

Thoda trade-off hota hai, par smart architecture se bahut compute bach sakta hai. MobileNet ka main jugaad hai: normal convolution ko do saste steps mein tod do.

Depthwise aur pointwise?

Haan. Pehle har channel pe alag spatial filter, phir 1×1 se channels mix. Kaam kaafi same feel, bill bahut kam.

Kam compute ki zaroorat kyu?

Phone camera app, AR filter, document scanner, offline face unlock — in sab mein model ko turant jawab dena hota hai. Cloud pe image bhejna slow, mehenga, kabhi privacy issue bhi. Isliye CNN ko lightweight banana padta hai.

LatencyUser button dabaye aur result aane mein kitna time.
BatteryHar multiply-add energy leta hai. Heavy model phone garam kar sakta hai.
MemoryWeights aur activations RAM mein fit hone chahiye.

Normal convolution ka cost

Example lo: input feature map 80×80×24, output channels 48, filter 3×3, stride 1 same padding. Normal conv mein har output channel har input channel ke 3×3 patch ko dekhta hai.

Cost_normal = H × W × n_C_in × f × f × n_C_out
  • H, W = output height/width
  • n_C_in = input channels
  • f = filter size
  • n_C_out = filters/output channels
Normal convCalculationMultiplications
80×80×24 → 80×80×4880×80×24×3×3×4866,355,200 ≈ 6.64 crore

Depthwise + pointwise: do saste steps

MobileNet v1 normal conv ko split karta hai:

  • Depthwise conv: har input channel par apna 3×3 filter. Channels mix nahi hote.
  • Pointwise conv: 1×1 filters se channels mix karke desired output channels banao.
StepCalculationMultiplications
Depthwise80×80×24×3×31,382,400
Pointwise 1×180×80×24×487,372,800
Total1,382,400 + 7,372,8008,755,200 ≈ 0.88 crore

Normal conv ke 6.64 crore ke saamne 0.88 crore. Ratio ≈ 0.132, yaani lagbhag 7.6x less computation. Phone khush, battery khush, user khush.

MobileNet v1

MobileNet v1 depthwise separable convolutions ko backbone bana deta hai. Normal conv ki jagah repeated depthwise + pointwise blocks. Do knobs bhi popular hain:

  • Width multiplier: channels kam/zyada karo. 1.0 full, 0.5 half-ish.
  • Resolution multiplier: input image resolution kam/zyada karo.
# MobileNet-v1 style block
x = DepthwiseConv2D(3, padding="same", activation="relu")(x)
x = Conv2D(48, 1, activation="relu")(x)  # pointwise channel mix

MobileNet v2: expansion, residual, bottleneck

MobileNet v2 ne block ko aur refined banaya. Pehle 1×1 se channels expand karo, beech mein depthwise conv, phir 1×1 se channels compress karo. Agar input-output shape same ho, residual shortcut add ho sakta hai.

Input→1×1 expand→Depthwise 3×3→1×1 project↻Residual

“Bottleneck” ka matlab yahan block ka output narrow ho sakta hai. V2 ka ek important idea linear bottleneck bhi hai: final projection ke baad ReLU nahi lagate, taaki compressed information zyada na kat jaaye.

EfficientNet: resolution, depth, width ko saath scale

Aksar log model bada karne ke liye random choice karte hain: image resolution badha do, layers badha do, ya channels badha do. EfficientNet ka idea: teeno ko balanced tarike se scale karo.

Better scaling = resolution ↑, depth ↑, width ↑ (saath-saath, fixed ratio se)
  • Resolution = input image bigger, detail zyada
  • Depth = layers/blocks zyada
  • Width = channels zyada

Jaise gym mein sirf biceps nahi, legs aur core bhi train karna. Sirf ek dimension badhaya to imbalance aa sakta hai.

Dhyan rakhna: “Less compute” ka matlab hamesha “same accuracy” nahi. Lightweight models trade-off karte hain; target device aur acceptable accuracy dono saath socho.
Yaad rakhna: MobileNet normal conv ko depthwise spatial step + pointwise channel mix mein todkar compute bachata hai; EfficientNet model ko balanced tarike se scale karta hai.

Dimaag mein aaye sawaal

Depthwise conv channels mix nahi karta, to kya information incomplete rahegi?

Isliye pointwise 1×1 step aata hai. Pehle har channel ka spatial pattern, phir channels ka mix.

MobileNet sirf phones ke liye hai?

Main motivation mobile/edge devices tha, par lightweight backbone server pe bhi useful ho sakta hai jab speed important ho.

EfficientNet mein compound scaling manually karna padega?

Usually pretrained EfficientNet variants ready milte hain. Concept samajhna useful hai: bigger model ko balanced tarike se grow karo.
