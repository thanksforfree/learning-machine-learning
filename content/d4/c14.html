Face recognition mein problem kya hai? Bas classifier bana do: employee-101, employee-102, employee-103...

Office mein kal naya employee join hua. Uski sirf ek Aadhaar-style photo hai. Classifier ko naye class ke liye retrain karoge?

Haan, woh to annoying hai.

Isliye face systems aksar “ye do photos same person hain kya?” seekhte hain. Naya person add karna = uski encoding database mein save karna.

Verification vs recognition

Verification (1:1)Claim check: “Main employee-102 hoon.” System stored employee-102 photo se compare karta hai. Phone unlock type.
Recognition (1:K)Unknown face ko K logon ke database se match karo. Office gate camera type.

Liveness bhi zaroori hai. Warna koi printed photo ya phone screen dikha ke gate khol de. Blink, depth, short video, IR pattern jaise checks practical systems mein use hote hain.

One-shot learning: ek photo se kaam chalana

Normal classifier har person ke many examples maangta hai. Face verification mein goal hai similarity function seekhna:

d(img₁, img₂) ≤ τ ⇒ same person
  • d = distance, chhota matlab faces similar
  • τ (tau) = threshold
  • Agar distance threshold se kam hai, access allow; warna reject.

Example: τ=0.70. Gate pe live photo aur database photo ka distance 0.42 hai, allow. Distance 0.91 hai, reject. Threshold zyada strict karoge to security high, par genuine log bhi kabhi reject ho sakte hain.

Siamese network: photo ko 128-number ID card banao

Siamese network mein same CNN dono photos pe chalta hai. Same weights, same processing. Har photo se 128 numbers ki encoding nikalti hai. Phir encodings ke beech distance nikaalte hain.

Triplet loss: anchor, positive, negative

Training mein teen images lo: Anchor A, Positive P (same person), Negative N (different person). Hum chahte hain A-P distance, A-N distance se margin α ke hisaab se chhota ho.

L = max(0, d(A,P) − d(A,N) + α)
  • d(A,P) = same person distance, chhota chahiye
  • d(A,N) = different person distance, bada chahiye
  • α = safety gap, jaise 0.2

Second row mein negative photo abhi too close hai. Model ko push karna padega: different person door jao, same person paas aao.

Mushkil triplets chuno

Agar negative bahut easy hai — jaise Anchor office employee aur Negative ek poster ka cartoon — loss already 0 hoga. Model kuch nahi seekhega. Useful triplets woh hain jahan negative thoda confusing ho: same lighting, similar age, similar pose. Training ke liye ek person ki multiple photos chahiye, taaki same person ke expression, angle, glasses, light variation model dekh sake.

Verification ko binary classification bhi bana sakte ho

Ek aur approach: do encodings lo, unka difference ya product features banao, phir small network sigmoid output de: same person ka probability. Ye direct “same/not same” classifier hai. Triplet loss distance space ko shape karta hai; binary classifier pair decision directly seekhta hai. Dono ideas practical systems mein mil sakte hain.

Database encodings pehle se save karo

Office gate pe 2000 employees hain. Har baar unki photos CNN se pass karna waste hai. Pehle se har employee ka 128-number encoding save karo. Gate pe live face ka encoding nikalo, database encodings se distance compare karo.

Employee photos→Encodings save→Live face encoding→Nearest match + threshold
Dhyan rakhna: Nearest person mil gaya matlab access allow nahi. Distance threshold bhi pass hona chahiye. Warna unknown visitor ko “database mein sabse zyada milta-julta” employee bana doge.
Yaad rakhna: Face recognition mein model person names yaad nahi karta; woh faces ko encoding space mein rakhta hai jahan same person paas aur different person door hote hain.

Dimaag mein aaye sawaal

128 numbers ka meaning kya hota hai?

Human-readable meaning nahi hota. Bas space aisa trained hai ki identity ke liye useful distances milen. Ek number “nose size” hi ho, zaroori nahi.

Threshold τ kaise choose karte hain?

Validation set pe distances dekho. False accept aur false reject ka trade-off choose karo. Bank app zyada strict threshold rakhega; office attendance thoda relaxed ho sakta hai.

Recognition mein 1:K slow nahi?

Database encodings precompute hote hain, isliye comparison fast vector distance hai. Bahut bade K ke liye nearest-neighbor search structures use kar sakte hain.

✍️ Ab tumhari baari (pehle khud socho, phir answer kholna)

Triplet loss: d(A,P)=0.30, d(A,N)=0.45, α=0.20. Loss?

L = max(0, 0.30 − 0.45 + 0.20) = max(0, 0.05) = 0.05.

τ=0.65 hai. Live face distance 0.62 aaya. Verification allow?

Distance threshold se kam hai, so similarity rule ke hisaab se allow. Real system mein liveness bhi pass hona chahiye.

Naye employee ko add karne ke liye poora model retrain karna zaroori?

Aksar nahi. Uski photo ka encoding nikaal ke database mein save karo. Model tabhi retrain hoga jab overall performance improve karni ho.
