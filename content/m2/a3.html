import tensorflow as tf
from tensorflow.keras import Sequential
from tensorflow.keras.layers import Dense

# 1. Banao: 3 layers
model = Sequential([
    Dense(25, activation="relu"),
    Dense(15, activation="relu"),
    Dense(1,  activation="sigmoid"),   # haan/na ka chance
])

# 2. Compile: galti kaise naapni hai + kaise sudharna hai
model.compile(loss=tf.keras.losses.BinaryCrossentropy(),
              optimizer=tf.keras.optimizers.Adam(learning_rate=0.001))

# 3. Fit: data do aur train karo
model.fit(X_train, y_train, epochs=100)

# 4. Use: naye data pe chance
chance = model.predict(X_new)
  • Dense = har neuron pichli layer ke har output se juda hai (“ghana” connection).
  • epochs=100 = poore training data pe 100 baar ghoomna. Jaise same chapter ko 100 revision passes.
  • X_train = ek table: har row ek example, har column ek feature.

Fit ke andar kya repeat hota hai?

model.fit ek line hai, par andar kya chal raha hota hai?

Socho gym trainer. Har batch pe model prediction karta hai, loss dekhta hai, backprop se slopes nikaalta hai, optimizer se weights thoda update karta hai. Phir next batch. Ye loop baar-baar.

Batch lo→Prediction→Loss→Backprop + update↻

Ek numeric feel lete hain. Maan lo 1000 training examples hain, batch size 100 hai, aur epochs = 5.

CheezHisaabMeaning
Batches per epoch1000 ÷ 100 = 10Ek epoch mein 10 updates
Total updates10 × 5 = 50Weights 50 baar sudhrenge
Prediction callsHar batch pe forward passModel baar-baar practice karta hai

Isliye epochs bahut kam hue to model under-practice. Bahut zyada hue to overfit bhi kar sakta hai. CV set isliye dost hai — woh batata hai kab rukna hai.

compile mein kya choose hota hai?

compile ko restaurant order samjho: model architecture kitchen hai, compile batata hai taste kaise judge hoga aur chef kaise improve karega.

LineMatlabExample choice
lossGalti ka billBinaryCrossentropy for haan/na
optimizerWeights ka update ruleAdam(0.001)
metricsReport card pe kya dikhanaaccuracy, precision, recall

Loss training ke liye main signal hai. Metric human-friendly report hai. Dono same hona zaroori nahi — fraud mein loss log loss ho sakta hai, metric recall.

Beginner checkpoint: TensorFlow code padhte waqt teen cheezein dhoondo: layers kitni hain, loss kya hai, optimizer kya hai. Ye teen mil gaye to model ka basic plan samajh aa jaata hai.

Ek aur practical baat: pehli baar model train karte waqt chhota run karo, jaise epochs=2. Agar code, shapes aur loss pipeline sahi chal rahe hain, tab long training chalao. Warna 100 epochs ke baad pata chalega ki label column hi galat tha — dard alag level ka.

Agar loss nan dikhne lage, learning rate bahut bada, data mein weird values, ya loss-activation mismatch ho sakta hai. Pehle chhota batch print karke sanity check karo.

Yaad rakhna: Architecture banao, loss + optimizer batao, data pe fit karo — baaki TensorFlow sambhal leta hai.

Dimaag mein aaye sawaal

Code ratna padega?

Nahi. Structure yaad rakho: banao → compile → fit → predict. Exact syntax documentation dekh ke likh sakte ho.

Library to black box hai, andar ka samajhna zaroori kyu?

Kyunki jab kuch galat hoga (aur hoga, sabke saath hota hai), to tumhe pata hona chahiye ki andar shapes, activations aur loss ka kya scene hai. Warna bas code idhar-udhar hilega, problem nahi.

Dense layer mein input shape kab dena hai?

Pehli layer ko kabhi-kabhi input shape batani padti hai, ya TensorFlow pehle batch dekh ke khud samajh leta hai. Beginner ke liye bas yaad rakho: rows = examples, columns = features.

Batch size kya choose karun?

Beginner ke liye 32, 64, 128 common choices hain. Chhota batch noisy par kabhi helpful, bada batch stable par memory zyada. Pehle default rakho, phir zaroorat pe tune karo.
